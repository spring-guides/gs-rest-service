Executive SummaryCapstone intent, scope, and documented outcomes ›

The capstone uses the Spring gs-rest-service guide as a bounded product surface and layers a professional GitHub Copilot operating model on top of it. The business goal captured in SCRUM-3 is intentionally small: deliver a personalized greeting endpoint. The organizational goal is larger: prove that GitHub Copilot can participate across the full SDLC under governance, with human approval, evidence capture, and traceability.

What was implemented

The repository documents an end-to-end SDLC sequence culminating in an approved verification report and PR package for SCRUM-3. The final report states that all planned phases were completed, including implementation, testing, verification, and pull request preparation.

Why it matters

The value is not just speed. The repo demonstrates how AI assistance can be constrained through prompts, agents, hooks, and approval gates so that generated output remains reviewable, auditable, and aligned to a named business story.

What is notable

The strongest signals in this repository are the formalized handoffs. Every phase has a dedicated agent, every phase produces an artifact, and downstream work is blocked until the human explicitly approves the prior result.

Agent CatalogSpecialized roles defined in .github/agents ›

The repository defines nine agent files. Eight are phase specialists. One is an orchestrator responsible for sequencing, prerequisites, and approval-gate enforcement. The catalog below is derived from the agent metadata stored in .github/agents/.

SDLC Orchestrator

Coordinates all phases, verifies required approved artifacts, delegates to phase agents, and prevents unauthorized phase skipping or self-approval.

Tools: read, search, agent

Requirements Agent

Retrieves the user story from Jira or Confluence and generates docs/requirements.md without self-approving the result.

Tools: read, edit, search, jira/*

Architecture Agent

Consumes approved requirements and creates the architecture artifact while preserving the human approval boundary before design review.

Tools: read, edit, search

Design Review Agent

Reviews the approved architecture against requirements and records risks, accepted recommendations, and coverage observations in docs/design-review.md.

Tools: read, edit, search

Implementation Planner Agent

Builds a dependency-ordered implementation plan from approved upstream artifacts and blocks implementation until that plan is human-approved.

Tools: read, edit, search

Implementation Agent

Owns the only phase allowed to modify application source and tests. It is also bound to pre-implementation and post-implementation hooks.

Tools: read, edit, search, execute

Code Review Agent

Assesses the completed implementation against approved artifacts and produces a review report before verification can begin.

Tools: read, edit, search

Verification Agent

Runs build and test evidence collection, validates acceptance coverage, and records PASS, FAIL, or BLOCKED outcomes in docs/verification.md.

Tools: read, edit, search, execute

PR Agent

Assembles the pull request package using approved SDLC artifacts and verification results. Its tool scope explicitly includes Jira, Confluence, and GitHub integrations.

Tools: read, edit, search, jira/*, confluence/*, github/*

Lessons LearnedWhat the repository shows about applying Copilot at SDLC scale ›

The repo's final report already records several lessons. Reading across the artifacts adds a few more pragmatic conclusions.

AI needs explicit constraints

The strongest part of this capstone is not freeform generation; it is the rule set that prevents premature implementation, self-approval, and undocumented scope drift.

Human approval remains structural

The orchestrator and global instructions both reinforce that human approval is not ceremonial. It is the actual gate that allows progression to the next phase.

Integration maturity can be uneven

Jira integration is concrete and validated in this repo. GitHub integration is present operationally through agent capability and workflow usage, but its MCP endpoint configuration is not stored here. That distinction should remain visible.

Small stories are useful proving grounds

A narrowly scoped feature like SCRUM-3 makes it feasible to evaluate the SDLC framework itself without confounding the exercise with large product complexity.
